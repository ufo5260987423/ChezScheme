# Review Checklists

Normative checklists for reviewing backend/compiler work. Rules prefixed `[RULE-…]` are enforced on the `x86-64-select`-lineage PRs; each rule points at the article that justifies it.

## A. Backend specialization (new/changed emitter or `define-instruction` clause)

- [ ] **[RULE-TRUTH]** Every flags-consuming sequence is derived from `../../03-backend/flags-truth-tables.md` (T-1/T-2 + derivation rules R-1…R-4). The PR description shows the derivation or cites the table cells.
- [ ] **[RULE-SYM]** If the clause is reachable with swapped arm/operand orders (condition inversion), the shortcut is checked in **both** orders per R-2. If one order is not supported, the clause declines it explicitly (guard/comment), never silently.
- [ ] **[RULE-TRUTH-NA]** FP sequences handle the unordered column: for `ucomisd`-driven `e`/`ne` an explicit `jp` escape is present, the skip offset is computed from emitted code (not a hand count), and its target is verified for **both** arm orders. `a/ae/b/be` need no escape (T-2); say so rather than emitting one "just in case". The computed displacement carries a bound assert (`safe-assert (fx<= 0 disp 127)`, the rel8 range) — see `fpsel-eq-skip`, `s/x86_64.ss:2681-2686`; a skip that can outgrow rel8 needs the longer form chosen explicitly, never an assert raised post-hoc.
- [ ] **[RULE-PRODUCERS]** The PR lists the passes that can produce the new instruction/emitter call (e.g. `rhs-inline`, `select-if`, `select-tail`, cpprim inlining) and argues which operand/flag shapes each can deliver — or adds a `safe-assert`/guard.
- [ ] **[RULE-ALIAS]** Destination/operand aliasing is handled at emit time by dispatching on the actual register relationships (`(equal? dest u)`, `(equal? dest v)`), not by a single preset sequence — the allocator may coalesce any pair (see `asm-fpsel-regs`, `s/x86_64.ss:2513`; the 2025 bootstrap bignum miscompile came from a preset clobbering a coalesced operand).
- [ ] **[RULE-UNSPILL]** Any new scratch introduced in an instruction clause is assigned by a plain `set!` before the self-referential `asm` (unspillable-conflict walk requirement; see the `(z mem)` clause history, commit 5b6227fb).
- [ ] **[RULE-IMM-DOMAIN]** Immediates flowing into encodings are checked against the *tagged* machine-word domain, never the source-level constant: a select between fixnums 40 and 8 works on machine words 320 and 64. The rule covers both hand-built imm byte sequences (a base above imm8 range silently truncates) and the emitters' range pickers: `emit addi` tops out at imm32 sign-extension — there is no imm64 path — so a tagged word outside `#x-80000000..#x7fffffff` must go through `emit movi` (full-quad movabs) or stay off the arithmetic form via an explicit clause guard (`s/x86_64.ss:471-490`). The same domain caution applies to *compiler-runtime arithmetic on tagged words*: the compiler's own `fx-` runs unchecked, and tagged operands may exceed the fixnum range (tagged most-negative-fixnum is -2^63), so differences and power-of-two tests are computed with exact integer arithmetic (`-`, `integer-length`), never `fx-`/`fxlength`. (Incidents: the arith select's first revision miscompiled `library.ss`'s define-syntax handling at bootstrap time, commit 4d0461ef; the addi imm32 ceiling miscompiled `(if (fx< x y) (most-negative-fixnum) (most-positive-fixnum))` under test-more's GC-stress configuration while test-some stayed green, commit c3f9762d — config-dependent reachability decides which suite catches it.)
- [ ] **[RULE-OPCODE]** Hand-assembled opcode bytes are verified against the ISA table, because the toolchain won't: `build` validates the *size* of each byte item, but any value passes, and a wrong opcode is a runtime `#UD`, not a compile error. The backend carries conditions as the low nibble shared with cmovcc (`04` = e, `0C` = l, …; `invert-cc-select`, `s/x86_64.ss:387-400`); setcc's full second byte is `0x90|cc` — `0F 94` sete, `0F 95` setne, `0F 9C` setl — so emitting the bare nibble produces `0F 04`, undefined in long mode and a SIGILL at first execution. Disassemble at least one shape per clause (`compile-file` + `xxd -p`, search the expected sequence: `0f94` sete, `0f2e` ucomisd, `0f44`/`0f45` cmove/cmovne). (Incident: `asm-fpsel=-arith`'s sete was first written `#x04`, found only when the probe ran — a bug class invisible to compilation; see `../03-backend/define-op-and-encoding.md`.)

## B. Tests accompanying a backend specialization

- [ ] **[RULE-REACH]** Every mat carries path evidence per `../reachability-rule.md`: a trace citation, a shape-forcing recipe (`../shape-forcing-recipes.md`), or an authoring-time trace check. The vacuity question is answered: "does this mat fail if the target code is removed?"
- [ ] **[RULE-EDGE]** Boundary inputs are enumerated from the truth table: for FP — both operand positions NaN, equal operands, ±0.0, infinities where meaningful; for integers — extremes, sign boundaries, mixed-sign comparisons.
- [ ] **[RULE-DIFF]** Where an independent reference exists, a differential test compares against it (recipe S-3 gives a branch-forced reference for predicates).

## C. Interface / layering changes

- [ ] The change does not push representation knowledge up a layer (mflatt's criterion from PR #1097 review): the *interface* sees machine words and operand shapes; `#t/#f` encodings stay inside the specialization.
- [ ] Architecture gating uses the `.def` capability-bit pattern (`setcc-instruction` in `s/a6.def`, `default.def #f`) rather than `architecture` checks scattered in passes.
- [ ] A new IR instruction updates: `np-languages.ss` production, `pred->…`/conversion tables, every backend's `define-instruction` (or an explicit "declined" path), and the mats.
- [ ] **[RULE-DEAD]** No primitive declaration plus backend clauses without a producer. Untestable clauses rot silently, and the rot can be semantic rather than stylistic: the boolean setcc form of flonum equality cannot serve both arm orders *at all* — unordered sets ZF=1, aliasing ordered-equal, so no sete/setne with any single jp placement yields the else value in both orders — invisible until a producer lands years later and exercises them. If the producer mapping is deferred, land the declaration commented with the reason, or land nothing. (Incident: `%fpsel=` was declared in `np-languages` with full x86_64 clauses and no producer; removed in d60a8ab1; reintroduced on purpose with computed skips in ef2396b5.)

## D. Process

- [ ] Commit messages distinguish *verified* claims (bootstrap rounds, mats at o=0/o=3, traces) from *inferred* ones, and say which.
- [ ] A fix for a masked-reachability bug adds the adversarial-shape mat **first** (fails before the fix, passes after), like `mats/fx.ms` "cover NaN in both arm orders".
